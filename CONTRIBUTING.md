## Getting Started

To ensure a positive and inclusive environment, please read our [Code of Conduct](CODE_OF_CONDUCT.md) before contributing.

### Local Development Setup

```bash
git clone https://github.com/firma-ai/openfirma.git
cd openfirma
just install
```

Install `just` first (`brew install just` on macOS, `cargo binstall just` elsewhere after installing `cargo-binstall`, or your distro package), then run `just install` to set up everything else: Rust toolchain check, protoc, cargo tools, and docs dependencies. See the [README](README.md) for more details on prerequisites and configuration.

## Issues

If you find a bug, please create an issue and we'll triage it.

- Please search [existing issues](https://github.com/firma-ai/openfirma/issues) before creating a new one.
- Please include a clear description of the problem along with steps to reproduce it. Logs from `firma doctor` and `firma monitor` really help.

## Pull Requests

We actively welcome your Pull Requests! A couple of things to keep in mind before you submit:

- If you're fixing an issue, make sure someone else hasn't already created a PR fixing the same issue. Link your PR to the related issue(s).
- If you're new, we encourage you to take a look at issues tagged with [good first issue](https://github.com/firma-ai/openfirma/labels/good%20first%20issue).
- If you're submitting a new feature, please open an [issue](https://github.com/firma-ai/openfirma/issues/new) first to discuss it before opening a PR.

Before submitting your PR, please run these checks locally:

```bash
just check     # fmt + lint + test + build + audit + dependency check
```

Running this before you create the PR will help reduce back and forth during review.

## Bazel Dependency Lockfiles

OpenFirma keeps Cargo-native dependency resolution separate from Bazel's rendered
external crate targets:

- `Cargo.lock` is the Cargo workspace lockfile used by `cargo` and `just check`.
- `Cargo.Bazel.lock` is the Bazel `crate_universe` rendering lockfile for the
  main workspace dependencies from `Cargo.toml` and `Cargo.lock`.
- `Cargo.Prost.lock` is a small Cargo lockfile for Bazel-only protobuf codegen
  tools: `protoc-gen-prost` and `protoc-gen-tonic`.
- `Cargo.Prost.Bazel.lock` is the Bazel `crate_universe` rendering lockfile for
  those protobuf codegen tools.
- `MODULE.bazel.lock` is Bazel's Bzlmod module resolution lockfile.

Keep the prost plugin lockfiles separate from `Cargo.lock` unless those tools
become Cargo-native dependencies. They are Bazel execution tools, not runtime or
build dependencies of OpenFirma's Cargo crates.

After changing `Cargo.toml`, `Cargo.lock`, `Cargo.Prost.lock`, `MODULE.bazel`,
or Bazel module/dependency wiring, refresh the Bazel lock state:

```bash
CARGO_BAZEL_REPIN=1 bazel mod tidy
```

Before submitting, verify the lockfiles are not stale:

```bash
just bazel-lockfile-check
```

CI runs the same check in the `Bazel Lockfiles` job. If it fails, keep the
lockfile changes generated by `CARGO_BAZEL_REPIN=1 bazel mod tidy` and rerun the
check.

CI also runs a Linux-only `Bazel Hermeticity` job. That job uses Bazel's strict
action environment, sandboxed execution, and C/C++ header layering checks via
`--config=hermeticity` to catch actions that accidentally depend on undeclared
host tools, files, headers, or environment variables before remote execution is
enabled.
